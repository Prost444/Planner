# Planner AI — планировщик ремонта с ИИ-агентом

Веб-приложение для пары, которая делает ремонт в маленькой квартире: 2D-план и 3D-вид, как в Planner 5D, плюс агент на Claude, который держит в контексте **точные размеры**, бриф и все пожелания, ищет мебель на российских маркетплейсах, проверяет, что она физически встаёт, расставляет её на плане и генерирует реалистичные рендеры по снимку 3D-сцены.

Проект создан под конкретную задачу — прихожая ≈ 3.5 м² в однушке со старым ремонтом (ниша 38×29 см у входа, стена с зеркалом 71 см, выключатель у двери, антресоль, паркет «ёлочка», стиль mid-century). Эта прихожая уже заведена как стартовый проект — см. `packages/shared/src/seed.ts`.

## Что умеет

| Блок | Возможности |
| --- | --- |
| **2D-редактор** | стены (с толщиной, привязкой к сетке 5 см и к углам 90°), полы с материалами, проёмы (дверь, двустворчатая, окно, проход, ниша) с петлями и стороной открывания, мебель с поворотом, линейка, подписи, замеры, undo/redo, авто-сохранение |
| **3D-вид** | стены с вырезанными проёмами и нишами, двери с углом открывания, процедурные текстуры пола (паркет «ёлочка», ламинат, плитка…), материалы стен, пресеты камеры (сверху, от входа, из углов), снимки сцены для рендеров |
| **Проверка размеров** | каждый предмет проверяется на пересечение со стенами, другими предметами, зонами открывания дверей и проходами; конфликты подсвечиваются красным и возвращаются агенту |
| **Агент (Claude)** | 23 инструмента: чтение плана, бриф, поиск товаров, чтение страниц товаров, каталог, расстановка с валидацией, свободные участки стен, материалы, правка стен/проёмов (только по просьбе), просмотр референсов, генерация рендера. Плюс встроенные `web_search` / `web_fetch` Claude |
| **Поиск товаров** | Wildberries (прямой API), Ozon / Яндекс Маркет / Авито / Лемана ПРО / Петрович / Hoff / Divan.ru — через `web_search` Claude или Tavily/SerpAPI; извлечение размеров Ш×Г×В и цен из страниц |
| **Рендеры** | снимок 3D-сцены (геометрия, камера, расстановка) + референсы стиля + фото выбранных товаров → OpenAI `gpt-image-1` или Google Gemini; без ключей возвращается снимок сцены |
| **Контекст** | бриф (стиль, пожелания, ограничения, бюджет, заметки), каталог, референсы, история чата — всё хранится в проекте и передаётся агенту каждым сообщением |

## Быстрый старт

Нужен Node.js ≥ 20.

```bash
npm install
cp .env.example .env      # впишите ANTHROPIC_API_KEY (и, по желанию, OPENAI_API_KEY / GEMINI_API_KEY)
npm run dev               # сервер http://localhost:8787 + клиент http://localhost:5173
```

Откройте http://localhost:5173 — стартовый проект «Прихожая — однушка» уже создан. Без ключа Anthropic редактор и 3D работают полностью, чат вернёт понятную ошибку.

Продакшен-режим (сервер раздаёт собранный клиент):

```bash
npm run build
npm start                 # http://localhost:8787
```

Данные (проекты, загрузки, рендеры, история чата) лежат в `apps/server/data/` (переопределяется `DATA_DIR`). Это обычные JSON и картинки — их легко бэкапить.

## Как с этим работать

1. **Уточните план.** Стартовая прихожая восстановлена по скриншотам Planner 5D, поэтому проверьте размеры: выберите стену/проём и поправьте цифры в «Свойствах», либо нарисуйте помещение заново (инструменты «Стена» → «Пол» → «Проём»). Какая из нижних дверей ведёт в спальню, а какая на кухню — в сиде отмечено как предположение.
2. **Заполните бриф** (вкладка «Бриф»): стиль, пожелания, ограничения. Всё, что вы говорите агенту, он тоже дописывает туда.
3. **Загрузите референсы и фото** (вкладка «Референсы»): фото прихожей — тип «фото», картинки в нужном стиле — «стиль». Референсы «стиль» автоматически участвуют в генерации рендеров.
4. **Общайтесь с агентом** (вкладка «Чат»). Примеры:
   - «Найди пуф 30×35 см в стиле mid-century до 6000 ₽ и поставь его под вешалку»
   - «Замени скамейку на советскую винтажную тумбу с Авито — подбери 3 варианта по размеру»
   - «Что можно разместить в нише 38×29 см у входа, не перекрыв выключатель?»
   - «Сгенерируй рендер от входа с отциклёванным паркетом и горчичными акцентами»

   Перед отправкой клиент снимает 4 ракурса 3D-сцены (галочка «снимки 3D») — по ним агент делает рендеры, сохраняющие реальную геометрию.
5. **Каталог**: найденные товары с ценами, ссылками и размерами (точно / примерно / неизвестно). Кнопка «на план» ставит товар в масштабе; агент делает то же через `place_item` с проверкой конфликтов.
6. **Рендеры**: галерея визуализаций; любую можно отправить в референсы и попросить «сделай так же, но…».

## Архитектура

```
packages/shared   модель плана (стены, проёмы, помещения, предметы, товары, бриф), геометрия,
                  валидация расстановки, описание плана для агента, стартовый проект, zod-схемы
apps/server       Fastify + Anthropic SDK: хранилище JSON, REST API, SSE-чат, цикл агента с
                  инструментами, адаптеры поиска (Wildberries API, Tavily, SerpAPI, парсер страниц),
                  провайдеры генерации картинок (OpenAI, Gemini, mock)
apps/web          Vite + React 19: SVG 2D-редактор, three.js / react-three-fiber 3D-вид с захватом
                  снимков, панели чата, каталога, брифа, референсов, рендеров, свойств
```

Ключевые файлы:

- `packages/shared/src/validate.ts` — `checkPlacement` (пересечения, зоны дверей, проходы) и `findFreeWallSegments` (свободные участки стен с доступной глубиной) — одна и та же логика в UI и у агента.
- `packages/shared/src/describe.ts` — текстовое описание проекта, которое агент получает каждым сообщением.
- `apps/server/src/agent/tools.ts` — определения и реализация инструментов агента.
- `apps/server/src/agent/agent.ts` — потоковый цикл Claude (streaming, server tools, prompt caching, компакция истории, обработка `refusal` / `pause_turn` / `max_tokens`).
- `apps/server/src/render/providers.ts` — провайдеры рендеров; добавить свой (fal.ai, Stability и т.п.) — реализовать интерфейс `ImageProvider`.
- `apps/web/src/editor2d/Editor2D.tsx`, `apps/web/src/viewer3d/Viewer3D.tsx` — редактор и 3D.

### Как агент «видит» размеры

Каждое сообщение пользователя начинается с блока `<project_state>`: помещения с площадью, стены с длинами, проёмы с координатами и стороной открывания, предметы с центром/поворотом/Ш×Г×В/высотой низа, свободные участки стен с глубиной, бриф, каталог, референсы и доступные снимки 3D. Инструменты `check_fit` / `place_item` / `move_item` возвращают конкретные конфликты («мешает открыванию двери в ванную», «пересекает стену входа»), а также подсказки, куда предмет поместится.

### Как делается рендер

`generate_render(view, prompt, product_ids, style_reference_ids)` берёт последний снимок выбранного ракурса, собирает промпт с фактами о помещении (материалы, список объектов с размерами, выбранные товары) и отправляет снимок + референсы стиля + фото товаров в image-модель с указанием сохранить геометрию, камеру и позиции объектов. Результат сохраняется в проект и показывается в чате и во вкладке «Рендеры».

## Переменные окружения

См. `.env.example`. Главные:

| Переменная | Назначение |
| --- | --- |
| `ANTHROPIC_API_KEY` | ключ Claude (обязателен для агента) |
| `ANTHROPIC_MODEL` / `ANTHROPIC_EFFORT` | модель (по умолчанию `claude-opus-5-5`) и уровень усилия |
| `OPENAI_API_KEY` или `GEMINI_API_KEY` | генерация рендеров (`gpt-image-1` / Gemini image) |
| `TAVILY_API_KEY` / `SERPAPI_API_KEY` | дополнительный поиск по маркетплейсам (необязательно — есть `web_search` Claude) |
| `AGENT_WEB_SEARCH` | включить встроенный веб-поиск Claude (по умолчанию `true`) |
| `DATA_DIR`, `PORT` | хранилище и порт сервера |

Если сервер работает за корпоративным HTTPS-прокси, запускайте его с `NODE_USE_ENV_PROXY=1`, чтобы `fetch` (поиск, страницы товаров, image-API) ходил через `HTTPS_PROXY`.

## Ограничения и честные оговорки

- **Маркетплейсы блокируют ботов.** Ozon, Авито и Яндекс Маркет не отдают страницы серверу напрямую, поэтому основной канал — `web_search`/`web_fetch` Claude и `fetch_page_info` для сайтов, которые это позволяют. Wildberries отвечает через свой публичный JSON (может возвращать 403 для датацентровых IP). Размеры, извлечённые из заголовков, помечаются как «примерно» — агент обязан уточнять их перед расстановкой.
- **Рендер — это ИИ-картинка.** Геометрия в ней держится на снимке 3D-сцены, но точность гарантирует план, а не картинка. Для лучшего совпадения ставьте мебель на план до генерации.
- **Стартовая планировка — реконструкция по скриншотам**, не обмер. Проверьте размеры.
- **Один пользователь за раз на проект**: пока агент работает, редактор блокируется, чтобы изменения не затирали друг друга; одновременная правка с двух устройств разрешается по принципу «последняя версия с сервера» (409 → перезагрузка проекта).
- Приложение рассчитано на локальный или домашний запуск: авторизации нет.

## Разработка

```bash
npm run typecheck      # tsc по всем пакетам
npm test               # vitest: геометрия и валидация расстановки
npm run build          # сборка клиента + проверка сервера
```

Горячие клавиши в 2D: `R` — повернуть предмет на 90° (`Shift+R` — 15°), `Delete` — удалить, `Ctrl+Z` / `Ctrl+Y` — отмена/повтор, `Esc` — отменить инструмент, колесо — зум, пробел или правая кнопка — панорама.
